# M4：Adapter 与插件体系

**阶段目标：** 建立平台适配器的版本化合约、能力发现与受控运行机制，使平台差异不侵入 Core，同时限制插件对账号、凭据和本地数据的访问。

**用户价值：** 平台接入可按统一规范扩展；用户能看清插件能做什么、申请了什么权限，并可授权、禁用或恢复故障插件。

**状态：** 需求拆分完成；实现状态待项目跟踪。

## 前置条件

M1、M3 通过验收。M3 的账号、凭据与会话服务是插件访问账号能力的唯一入口。

## 范围

- Platform Adapter 合约及版本兼容规则。
- 插件 Manifest 校验：ID、名称、版本、类型、入口、Runtime、MCP 配置、能力与权限声明。
- 能力状态：`supported`、`unsupported`、`restricted`、`experimental`、`unavailable`。
- `content.read` 与 `content.publish` 按 `ContentKind`（视频、图文、图文文章、纯文章）分别声明和验证；Adapter 载荷保留形态所需的正文、封面和媒体顺序。
- 插件发现、安装、权限审查、授权、启用、禁用、错误和卸载生命周期。
- 官方插件随应用分发；独立插件进程的启动、健康检查、停止、超时、崩溃上报和恢复。
- 网络、账号凭据、工作区、平台能力等权限由 Core 代理并执行用户授权策略。
- 插件兼容性测试框架与开发文档。

## 功能要求

1. Manifest 是声明/申请，不是授权凭证；未知字段、非法版本或不兼容合约不得静默接受。
2. 在启用前展示插件来源、版本、申请权限、能力与风险；用户可逐项授权或拒绝。
3. 插件访问凭据必须通过 Credential Service 按账号授权，不能读取 Keychain 或浏览器 profile 的原始存储。
4. 默认不授予任意工作区读写；仅授予完成已授权能力所需的最小接口。
5. Core 根据真实运行探测和 Adapter 验证结果展示逐形态能力状态，不能仅复制插件自报声明，也不能用笼统的“支持发布”掩盖部分形态不支持。
6. 插件异常、超时或协议违规要形成日志和用户可见错误，不应导致桌面 Core 或其他插件崩溃。
7. 支持停止/禁用、卸载和受支持版本的回退；卸载时清理插件文件并按明确规则保留/删除插件数据。
8. 独立进程不等同于强安全沙箱；不受信任代码必须在批准强隔离方案前禁止安装或明确标记不可受信任。
9. `PublishInput` 必须显式携带 `ContentKind` 和该形态所需的完整媒体引用/顺序；Core 通过受控资产服务提供素材，Adapter 不需要任意工作区访问权。

## 验收标准

| ID       | 验收场景      | 通过条件                                                                                                                    |
| -------- | ------------- | --------------------------------------------------------------------------------------------------------------------------- |
| M4-AC-01 | Manifest 校验 | 合法 Manifest 被解析；缺字段、错误类型、不支持版本和非法能力被拒绝并给出字段级错误。                                        |
| M4-AC-02 | 权限审查      | 首次启用时展示来源、版本、权限和能力；未授权的账号凭据/网络/工作区操作被 Core 拒绝。                                        |
| M4-AC-03 | 适配器注册    | 至少一个测试 Adapter 可通过公开合约注册，Core 可列出其身份和能力状态；平台差异不需修改公共账号模型。                        |
| M4-AC-04 | 能力可信      | Adapter 声明支持但运行检查失败时，UI 展示不可用/错误状态而非可用；受限或实验能力有明确标识。                                |
| M4-AC-05 | 生命周期      | 可完成发现→安装→权限审查→授权→启用，并执行禁用、卸载；每次状态变更均有可追踪结果。                                          |
| M4-AC-06 | 故障隔离      | 杀停或使测试插件超时后，Core 和另一个健康插件仍可工作；故障插件可查看错误并重启。                                           |
| M4-AC-07 | 版本兼容      | 不兼容插件版本不可启用；回退后 Adapter 合约版本及已授予权限状态符合迁移策略。                                               |
| M4-AC-08 | 安全边界      | 插件不能绕过 Core 直接访问 SQLite、原始凭据或未授权工作区路径；测试记录证明访问被拦截。                                     |
| M4-AC-09 | 运行时决策    | 发布实现前完成 ADR，写明首期运行时、权限隔离能力、信任模型、平台差异和不支持场景；不得将“独立进程”描述为安全沙箱。          |
| M4-AC-10 | 分形态能力    | 测试 Adapter 可声明某账号支持图文但不支持视频；UI/Core 分别呈现两种状态，拒绝无能力的发布输入，且不影响其他形态。           |
| M4-AC-11 | 载荷完整性    | 视频发布输入包含视频文件和封面，图文发布输入保留图片顺序/封面，文章发布输入包含正文；缺少形态必需载荷时在调用平台前被拒绝。 |

## 不在本阶段

- 面向公众的插件市场、自动更新分发和社区信任体系（MVP 暂缓）。
- 任意第三方代码插件的强安全隔离承诺。
- 未经单独验证的所有平台功能实现。
