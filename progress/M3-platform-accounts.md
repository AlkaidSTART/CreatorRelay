# M3：平台账号体系

**阶段目标：** 建立平台、账号、会话与凭据的统一本地管理模型，为 Adapter 和业务操作提供可信的账号边界。

**用户价值：** 用户可以在一个平台下管理多个账号，完成登录、检查状态、重新授权和安全删除；不同账号会话相互隔离。

**状态：** 已验收（2026-11-25）。

## 范围

- `Platform → Accounts → Platform Sessions` 三级关系。
- 平台目录及账号别名、头像、昵称、UID、启用状态和默认账号设置。
- 认证方式入口：内置 WebView、系统浏览器回退、官方 OAuth（平台支持时）。
- 账号状态机：`UNAUTHORIZED → AUTHENTICATING → ACTIVE`，以及 `EXPIRED`、`NEEDS_REAUTH`、`ERROR`、`DISABLED`。
- 通过操作系统安全凭据存储管理密码、Cookie、Token 等敏感凭据；SQLite 只保存凭据引用及非敏感元数据。
- 按平台和账号隔离浏览器会话；检查登录状态必须依据实际探测结果。
- 账号删除时显式确认凭据与会话清理范围；历史作品保留/删除采用独立决策。

## 功能要求

1. 同一平台可创建多个账号；每个账号唯一归属一个平台，具备稳定内部 ID。
2. 认证结束后验证平台身份，并保存经过校验的账号信息；未验证身份不能显示为已连接。
3. 平台目录须显示认证方式和已验证/未验证能力边界；不支持的登录方式不可伪装为可用。
4. 会话状态过期或检查失败时标记为 `NEEDS_REAUTH` / `ERROR`，不得仅凭本地 Cookie 文件存在认定有效。
5. 账号之间使用独立凭据引用与浏览器 profile；A 账号登出、重登或删除不应影响 B 账号会话。
6. 删除账号前明确提示会删除的凭据、会话数据及将保留的运营历史；确认后执行并记录脱敏操作日志。
7. 浏览器会话数据按敏感数据保护，不默认作为普通文件展示或明文打包备份。

## 验收标准

| ID       | 验收场景       | 通过条件                                                                                                |
| -------- | -------------- | ------------------------------------------------------------------------------------------------------- |
| M3-AC-01 | 多账号管理     | 同一平台添加两个账号后，列表显示各自别名/状态；编辑或禁用其中一个不改变另一个。                         |
| M3-AC-02 | 登录与身份校验 | 支持的认证流程完成后显示验证得到的 UID/昵称；身份获取失败时显示错误，不创建虚假的 ACTIVE 状态。         |
| M3-AC-03 | 登录状态检测   | 将测试凭据模拟为过期后执行检查，账号进入需重新授权状态并阻止依赖该账号的后续任务。                      |
| M3-AC-04 | 凭据安全       | SQLite 与日志中仅能找到凭据引用/非敏感状态，无法找到测试密码、Cookie、Token 的明文值。                  |
| M3-AC-05 | 会话隔离       | 两个账号的浏览器 profile 标识和存储容器不同；在一个会话写入的测试 Cookie 不会出现在另一个账号会话中。   |
| M3-AC-06 | 浏览器回退     | 平台不兼容内嵌 WebView 时，用户可按配置转入系统浏览器/人工登录流程，并能看到需要手动完成的步骤。        |
| M3-AC-07 | 账号删除       | 删除前展示凭据、会话与历史作品处理说明；确认删除后对应凭据/会话按规则清理，历史作品不会被意外连带删除。 |
| M3-AC-08 | 状态真实       | 仅存在本地 profile 文件但平台验证失败时，账号不得呈现为已登录/ACTIVE。                                  |

## 不在本阶段

- 通用插件 Manifest、第三方插件进程和能力注册（M4）。
- 所有目标平台的认证实现；每个平台须独立验证官方授权、登录机制和自动化政策。
- 发布、内容同步和指标采集（M6）。

## 已落地决策

- 当前构建暂不启用账号级独立 WebView；Bilibili 使用系统浏览器人工登录后调用官方身份接口校验，其他平台明确标记人工流程或未开放（PRD §16.4）。
- 系统 Keychain/凭据存储不可用时直接失败，不降级为 SQLite 或普通文件明文存储。
- 账号删除清理 Keychain 凭据和会话容器；外部作品历史通过 `ON DELETE SET NULL` 保留并解除账号关联。
