# M2：本地内容工作区

**阶段目标：** 建立本地优先的内容包工作区，使视频、图文、图文文章和纯文章的元数据、正文、媒体资产与 SQLite 索引各有清晰职责，并具备搜索、迁移和恢复能力。

**用户价值：** 用户可在本机创建、整理、导入、导出和搜索四类内容；视频和图片顺序不会因编辑器只支持 Markdown 而丢失，文件外部变化也不会被应用覆盖。

**状态：** 实现进行中；版本策略已冻结；未验收（多项 M2 标准尚未验证）。

**当前实现进度（2026-11-25）：** Rust 工作区核心已有 Markdown CRUD、索引同步、相对路径校验和哈希冲突拒绝；本轮增加应用数据目录 bare Git 历史、人工版本提交/差异/恢复、旧快照迁移、Markdown 导入/导出入口、文章素材导入/预览/定位、引用素材内容包导出/重导入、索引重建入口、全文搜索与外部修改决策提示。四类内容包及清单模型仍未完成；此进度说明不等于 M2 验收通过。

## 前置条件

M1 的桌面应用、IPC、SQLite 迁移及授权数据目录机制已通过验收。

## 范围

- 设置/选择工作区根目录，并限制应用文件读写在用户授权的工作区内。
- 统一内容包与目录组织：`video`、`image_text`、`rich_article`、`plain_article`；建议结构见 PRD §5.3。
- 内容清单解析与索引：内容 ID、`kind`、标题、标签、状态、封面、媒体顺序和平台稿关联。
- 图文文章及纯文章以 Markdown 文件保存正文；视频和图文以内容清单及媒体文件共同保存主内容。
- 视频、图片、封面、字幕和附件的本地存放、相对引用、基础元数据与完整性检查。
- 文件夹、标签、按内容形态筛选、全文搜索、导入/导出。
- 外部文件变化检测、索引更新与索引重建。
- 版本历史采用应用数据目录内 Git bare 仓库；当前实现范围只记录主稿 Markdown。视频、图文与平台稿来源版本尚未纳入，按后续内容包版本决策处理（[ADR-001](../docs/adr/ADR-001-article-version-history.md)）。
- 既有 Markdown 文章向 `plain_article` / `rich_article` 的迁移边界与未知字段保留。

## 功能要求

1. 每个内容包必须有稳定 ID 和且仅有一个 `kind`：`video`、`image_text`、`rich_article`、`plain_article`。
2. 内容包清单是形态、元数据、封面和媒体顺序的权威来源；SQLite 只保存索引、标签/搜索字段、状态、哈希及关联，不保存会与文件冲突的权威副本。
3. `rich_article` 与 `plain_article` 的正文以 Markdown 文件为权威来源；`video` 与 `image_text` 不要求生成 Markdown 正文，不得用空 Markdown 文件伪装内容主体。
4. 图片和视频的展示顺序、封面归属、媒体角色与说明必须持久化；重启或重新打开内容包后顺序不得改变。
5. 素材引用使用可迁移的相对路径或稳定资源 ID，不把绝对路径写入可移植内容；写入前拒绝目录穿越和工作区外路径。
6. 内容清单 Schema 校验已知字段，同时保留未知字段；保存不得静默删除用户自定义元数据。
7. 检测到外部编辑时，重新读取并刷新索引；如应用中存在未保存修改，提示冲突并让用户选择，不覆盖磁盘文件。
8. 索引缺失、损坏或与文件不一致时，可从内容包文件重建索引；重建不得删除或改写 Markdown 正文、媒体文件或清单。
9. 导入 Markdown 默认生成 `plain_article`；含可解析图片引用的 Markdown 可生成 `rich_article`。导入已有内容包须校验 `kind` 和素材完整性。
10. 修改内容形态不得原地改写 `kind`；跨形态转换必须创建新内容包，并保留来源内容 ID 和版本。
11. 内容版本恢复须恢复正文（文章形态）、清单元数据和媒体顺序；恢复前现有版本仍可追溯。
12. 视频基础检查至少记录文件可读性、容器/格式（如可识别）、时长和尺寸；图片至少记录可读性、尺寸和格式。不可识别的字段标记为未知，不得伪造。

| M2-AC-07 | 外部修改冲突     | 外部修改已打开的文章正文或内容清单；应用识别新版本，存在未保存编辑时不覆盖外部文件并要求用户解决冲突。         |
| M2-AC-08 | 索引重建         | 删除测试数据库中的工作区索引后执行重建，可恢复可解析内容的索引；重建前后正文、清单和媒体文件哈希一致。         |
| M2-AC-09 | 导入/导出        | 导入 Markdown 生成正确文章形态并保留可识别元数据；导出视频、图文和文章内容包后可由应用重新导入且素材引用有效。 |
| M2-AC-10 | 跨形态转换保护   | 将纯文章派生为图文时生成新的内容包并保留来源 ID/版本；原内容 `kind`、正文和媒体不变。                          |
| M2-AC-11 | 路径安全         | 对工作区外路径及目录穿越输入进行读写时被拒绝；正常工作区内操作成功。                                           |
| M2-AC-12 | 版本恢复         | 创建至少两个可区分版本后，可查看差异并恢复选定版本；文章正文、封面和媒体顺序按版本恢复，现有版本仍可追溯。     |
