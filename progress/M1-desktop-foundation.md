# M1：桌面基础设施

**阶段目标：** 建立可运行、可升级、职责边界清晰的桌面应用与本地数据底座，为后续业务模块提供稳定入口。

**用户价值：** 用户可以安装并启动 CreatorRelay，在统一桌面窗口中访问各功能模块；应用能够安全地保存基础业务数据并支持数据库升级。

## 范围

- Tauri 2 桌面容器，React + TypeScript 前端与 Rust Core。
- 基础导航及模块页面占位/入口（Dashboard、Studio、Publishing、Content、Analytics、Assistant、Platforms、Settings）。
- 经校验的 Tauri Commands / Events IPC；业务逻辑由 Rust Service 承担。
- SQLite 初始化、版本化迁移、事务和错误反馈。
- 应用数据目录、日志基础设施及可诊断启动错误。
- 工作区/数据目录的初次配置入口；实际内容包、Markdown 与媒体工作区操作归 M2。

## 功能要求

1. 前端通过受控 IPC 调用 Core，不直接访问 SQLite、任意文件路径或凭据。
2. IPC 边界校验输入并返回稳定、可展示的成功/错误结果；不得把错误静默吞掉。
3. 数据库表结构只能通过版本化迁移变更。迁移失败应保留原始数据库并提供可诊断错误，不得留下半迁移状态。
4. 应用可显示核心模块导航及当前页面；尚未交付的模块显示为规划/未开放，而非伪装为已完成。
5. 日志可用于定位启动、IPC 和迁移错误，但不得记录密码、Cookie、Token 或 API Key。

## 验收标准

| ID       | 验收场景   | 通过条件                                                                                                             |
| -------- | ---------- | -------------------------------------------------------------------------------------------------------------------- |
| M1-AC-01 | 首次启动   | 在支持的目标桌面环境安装并启动应用，主窗口及基础导航可见；没有可恢复数据库时自动初始化数据库并记录当前 schema 版本。 |
| M1-AC-02 | 模块导航   | 用户可在已开放的导航项之间切换；未开放模块有明确占位状态，不出现无响应入口或虚假业务数据。                           |
| M1-AC-03 | IPC 边界   | 前端通过 Rust IPC 完成一个代表性读写操作；非法参数被拒绝并返回可识别错误，前端没有直接数据库访问路径。               |
| M1-AC-04 | 数据库升级 | 从至少一个旧 schema fixture 执行迁移后，版本正确、数据完整；迁移失败时事务回滚或恢复到可用状态，原数据未被破坏。     |
| M1-AC-05 | 重启持久化 | 写入代表性业务记录后关闭并重启应用，记录仍可读取；初始化不会重复创建或覆盖数据。                                     |
| M1-AC-06 | 日志脱敏   | 使用包含模拟敏感字段的失败请求验证日志，日志保留错误上下文但不含凭据值。                                             |
| M1-AC-07 | 可诊断性   | 人为制造 IPC 或数据库错误时，用户看到明确失败反馈，日志能定位错误阶段，应用不会因单次业务异常崩溃。                  |

## 不在本阶段

- 真实平台登录、插件执行、发布、AI 对话和 MCP 工具调用（后续阶段）。
- 云同步、团队协作和完整插件市场（MVP 暂缓）。
