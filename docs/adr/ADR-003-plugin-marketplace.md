# ADR-003：第三方插件市场保持关闭，先完成签名与强隔离

- **状态：** Accepted（2026-11-25，M8 生态治理决策）
- **决策范围：** 第三方 Adapter 的安装、分发、市场开放和应急下架
- **背景：** M4 已允许加载随应用分发的官方 Adapter，但独立进程不等于强沙箱。M8 需要决定是否开放第三方插件安装或市场。当前 Windows/Linux 只有进程隔离，且没有远程签名撤销链和第三方发布签名验证。

## 决策

1. **市场保持关闭。** `marketplace-policy.json` 的 `decision` 固定为 `closed`，仅允许 `bundled_official_only`。
2. **第三方安装继续禁用。** UI 不提供第三方安装入口；Adapter catalog 只包含内嵌官方 Manifest。
3. **不提供“受控试点”例外。** 在强隔离、签名、撤销和应急下架全部通过前，不能以试点名义降低审查标准。
4. **权限升级必须重新审查。** 插件版本更新后，新权限的授权状态清空；旧权限只保留新旧 Manifest 的交集。用户拒绝权限后，Core hostCall 拒绝该能力，插件不能自行绕过。
5. **版本回退可执行。** 更新/回退前必须禁用；保留上一版 Manifest 与哈希，并记录 `VERSION_CHANGED` / `ROLLED_BACK` 审计事件。
6. **开放条件机器可读。** 六项门禁在 `marketplace-policy.json` 中逐项记录证据与通过状态；任何必需门禁失败时，策略校验必须拒绝 `open` 或 `controlled_pilot`。

## 门禁

| 门禁 | 当前结果 | 证据 |
| --- | --- | --- |
| 威胁评估 | 通过 | 本 ADR、ADR-002、M4 安全边界测试 |
| 来源与签名 | 未通过 | 只有内嵌 Manifest 哈希校验，没有第三方发布签名链 |
| 强隔离 | 未通过 | macOS 有 sandbox-exec；Windows/Linux 仅进程隔离 |
| 更新与回滚 | 通过 | M4 版本更新/回退与权限交集测试 |
| 权限撤销 | 通过 | 逐项授权、Core 代理拒绝路径 |
| 应急下架 | 未通过 | 没有远程签名吊销/强制卸载机制 |

## 后果

- M8 可以验证官方适配器兼容性、权限升级和人工发布路径，但不能宣称开放第三方生态。
- 新增平台只能以官方内嵌适配器或人工流程交付。
- 后续开放市场需要独立的安全评审、签名基础设施、跨平台强隔离和应急响应演练。
