# CreatorRelay MVP 需求说明

**版本：** V0.1  
**日期：** 2026-11-25  
**状态：** MVP 范围基线（待平台与用户验证）  
**关联文档：** [CreatorRelay PRD V0.3](./CreatorRelay-PRD-v0.3.md)

> 本文将 PRD 中的长期产品愿景收敛为首个可验证版本。若本文与 PRD 的长期功能清单冲突，MVP 开发范围以本文为准；PRD 继续作为后续版本愿景和总体架构参考。本文不代表掘金、CSDN 的官方接口或自动化能力已得到验证。

---

## 1. MVP 决策摘要

CreatorRelay MVP 是一款面向中文技术创作者的**本地优先 Markdown 多平台创作与分发桌面工作台**。首版聚焦一条链路：

> 写一份主稿 → 生成并编辑掘金、CSDN 平台稿 → 检查和复制内容 → 打开平台完成手动发布 → 在本地记录发布结果。

| 决策 | MVP 基线 |
|---|---|
| 首要用户 | 使用 Markdown 写技术文章、需要向多个内容平台分发的中国个人创作者 |
| 核心平台 | 掘金、CSDN；只承诺本地稿件适配和人工发布辅助，不承诺平台 API 能力 |
| 核心价值 | 减少重复排版与分发准备工作，保留本地内容所有权和可恢复历史 |
| 发布模式 | 默认人工发布辅助；用户检查后复制内容并打开平台。无自动发布、定时发布 |
| 内容权威 | Markdown 文件是正文唯一权威来源；SQLite 只保存索引、元数据和本地记录 |
| AI | BYOK；用户明确选择发送的内容后才发往模型；模型输出须由用户检查和应用 |
| 插件 | 仅内置、随应用发布的官方适配器；不运行第三方代码，不提供插件市场 |
| 桌面平台 | MVP 目标为 macOS 与 Windows；Linux 暂不作为首发验收平台 |
| 验证目标 | 5 位目标用户试用，至少 4 位无需指导、15 分钟内完成核心任务 |

## 2. 用户与问题

### 2.1 目标用户

首版服务于个人技术创作者：能够使用 Markdown 或愿意使用 Markdown，持续产出技术文章，并需要把一份内容整理为多个平台版本。典型用户包括技术博主、独立开发者和工程师作者。

### 2.2 当前痛点

1. 一篇文章需要在多个平台重复排版、删改和复制。
2. 主稿与各平台版本容易分叉，难以知道版本来源和差异。
3. 图片、封面等素材散落在不同目录，搬运时容易丢失或引用失效。
4. 发布准备过程分散，发布链接和状态缺少统一的本地记录。
5. 使用云端 AI 时，作者不清楚哪些内容被发送，也难以安全地把 AI 结果并入原稿。

### 2.3 MVP 不服务的主要场景

- 团队协同、多人审批和多席位权限管理。
- 非技术长文、短视频剪辑、直播或全品类社交媒体运营。
- 以自动发布、统一账号登录托管或全平台实时数据分析为核心的场景。

## 3. 目标与成功指标

### 3.1 产品目标

- 让用户在一个本地工作区中创建、编辑、检索和恢复 Markdown 主稿。
- 从同一主稿生成相互独立的掘金稿和 CSDN 稿，并支持用户进一步编辑。
- 提供清晰、可检查的人工发布准备流程，并记录用户手动确认的发布信息。
- 让用户明确控制发送给 AI 的内容，并能决定是否采纳生成结果。

### 3.2 首轮可用性验证

邀请 5 位符合目标画像的用户，在未接受操作指导的情况下完成第 12 节的任务。成功标准：

- 至少 4/5 位用户在 15 分钟内完成主稿创建、生成两份平台稿、编辑其中至少一份并进入人工发布准备流程。
- 试用期间不得发生稿件静默丢失、平台稿覆盖主稿、用户未授权内容被发送给 AI 等严重问题。
- 记录任务完成时间、求助次数、失败步骤和用户认为最有价值/最困惑的环节；这些记录用于下一轮产品决策，不以主观满意度替代任务完成率。

该目标是产品验证门槛，不是对所有用户或机器环境的性能承诺。

## 4. MVP 范围

### 4.1 P0：首发必须具备

#### A. 本地工作区与内容管理

- 首次启动时选择或创建工作区；清楚展示当前工作区路径。
- 创建、打开、重命名、归档和删除主稿；删除前明确告知影响并提供确认。
- 编辑 Markdown，提供可读的编辑与预览体验，支持标题、段落、列表、引用、代码块、链接、图片引用等常见结构。
- 自动保存；显示保存状态与失败原因。应用异常退出或磁盘写入失败时，不得伪装为已保存。
- 支持按标题、正文和标签搜索；支持按最近编辑时间排序。
- 支持导入和导出 Markdown 文件；导入冲突时不得静默覆盖已有文件。
- 素材可从文件导入工作区，编辑器可插入工作区内的相对路径引用；删除稿件不得未经确认地删除仍被其他稿件引用的素材。
- 外部程序修改中的文件被检测到时，提示用户选择保留磁盘版本、载入外部版本或另存副本；不得静默覆盖外部修改。

#### B. 版本恢复与备份

- 用户能够查看主稿的平台版本历史，并将旧版本恢复为一个新的当前版本；恢复操作不销毁被恢复前的版本。
- AI 应用结果和批量替换等可能显著改变正文的操作，应用前保留可恢复的前一版本。
- 每个文档至少保留最近 30 个可恢复版本；容量或保留策略触顶时，界面明确告知并按确定的规则清理旧版本。
- 提供手动导出和恢复工作区备份的能力；恢复前展示目标位置和覆盖范围，并要求用户确认。
- MVP 不要求云端/异地备份，也不保证可恢复操作系统故障、磁盘损坏或用户主动永久删除后的数据。
- 版本历史的底层实现（Git 或应用快照）属于工程决策，但不得改变上述用户可见行为。

#### C. 平台稿与人工分发

- 支持从一份主稿创建掘金稿和 CSDN 稿；平台稿是独立可编辑的本地文件，不得因主稿变更而自动覆盖。
- 每个平台稿记录其来源主稿及生成时的主稿版本标识；主稿更新后提示平台稿可能过期，允许用户比较、保留或重新生成。
- 支持查看主稿与平台稿的差异，至少能够识别正文文本增删；不要求复杂的富文本合并。
- 提供平台稿预览、平台格式检查和发布准备页。检查项基于经过验证并可维护的规则；无法确认的规则应标为提示，不得显示为平台保证。
- 发布准备页包含平台、平台稿、待复制内容、素材检查结果和打开平台入口。用户明确点击后，应用才复制选定内容或打开外部网页。
- 首版复制的是平台稿 Markdown 源文，并提供 Markdown 文件导出；不承诺粘贴到平台编辑器后格式完全一致。图片等本地素材列出路径与检查状态，用户自行上传到平台；应用不自动上传媒体。
- 用户完成外部发布后可手动记录发布链接、发布时间和备注；未填写的外部数据保持未知，不推断为已发布。
- 人工发布辅助必须允许用户继续在平台自行登录、验证和完成发布；产品不保存平台密码、Cookie 或登录会话。

#### D. AI 辅助创作

- 首发提供至少一个 OpenAI-compatible API 配置入口：端点、模型名称和用户自备密钥；密钥存入操作系统凭据存储，界面可验证连接。若目标系统无法提供安全凭据存储，应禁用持久化密钥并明确告知，而非明文落盘。
- 支持标题/摘要建议、润色和将主稿转为掘金或 CSDN 草稿等有限任务；用户可编辑提示词或提供补充要求。
- 发送请求前展示将发送给服务商的内容范围，并提供取消机会。默认仅发送用户当前明确选择的文档/片段和本次必要指令，不自动上传整个工作区、素材库或历史对话。
- AI 返回内容先作为候选结果展示；用户可复制、局部应用或整体另存为平台稿。未经用户确认不得改写主稿、触发发布或执行外部操作。
- AI 请求失败、超时、限流和响应格式不兼容时，保留原文并展示可理解的错误信息；不得丢弃用户未保存的编辑。
- MVP 不承诺模型输出的事实正确性、平台审核通过率或特定模型服务的可用性。

#### E. 桌面应用基础

- 基于现有 Tauri 2 + React + TypeScript + Rust 工程实现核心工作流。
- 提供工作区、稿件列表、编辑/预览、平台稿管理、AI 设置和发布准备等基础页面。
- 目标支持 macOS 与 Windows 的开发、打包和核心流程验收；各操作系统的安装、文件权限、凭据存储及更新行为分别验证。
- 所有破坏性本地操作（删除稿件、替换文件、恢复备份）必须显示影响并二次确认。

### 4.2 P1：有余力再纳入，不阻塞首发

- 自定义文章模板、快捷键配置、更多导入格式。
- 更丰富的 Markdown 扩展语法或高级差异视图。
- 批量导出多个平台稿。
- 可配置的备份保留策略和自动本地备份。
- 更多 OpenAI-compatible 服务连接预设。

P1 的实现不得挤占 P0 数据安全、恢复和核心链路验收。

## 5. 明确不做（MVP Non-goals）

- 自动发布、定时发布、自动登录、Cookie/Token 抓取或浏览器会话托管。
- 掘金、CSDN 或其他平台的官方 API 集成承诺；平台页面打开仅是人工辅助。
- 平台作品/账号数据自动同步、Dashboard 运营大盘、Analytics 指标比较。
- 统一管理多个平台账号、账号登录状态检测和跨平台授权。
- AI Agent 自主计划并执行多步骤任务、未经确认的写操作或发布。
- 对外提供 MCP Server、连接任意 MCP Server 或 MCP Host 能力。
- 第三方插件运行时、插件市场、任意脚本执行及工作区外文件访问。
- 团队协作、云同步、账号体系、移动端、Linux 首发支持。
- 图像编辑、视频剪辑、内容审核规避或平台风控绕过。

这些项目可进入后续路线图评估，但不应以抽象接口或预留页面的方式扩大 MVP 验收面。

## 6. 信息架构与核心页面

1. **工作区/稿件列表**：创建和搜索主稿，查看最近编辑、标签和本地发布记录。
2. **Studio 编辑页**：编辑/预览主稿，访问素材和版本历史。
3. **平台版本页**：列出掘金、CSDN 稿件状态、来源版本和差异；创建或重新生成平台稿。
4. **发布准备页**：最终预览、格式提示、复制内容、打开平台、手动记录外部发布链接。
5. **设置页**：工作区路径、AI 端点与模型配置、隐私说明、备份与恢复。

首版不需要独立的运营 Dashboard、账号中心或 Analytics 一级导航。

## 7. 核心对象与状态

### 7.1 内容对象

- **主稿（Master Draft）**：用户创作的 Markdown 权威文件。
- **平台稿（Platform Draft）**：由主稿创建、可独立编辑的本地 Markdown 文件，关联平台和来源主稿版本。
- **发布记录（Publish Record）**：用户手工登记的平台、平台稿、外部链接、发布时间和备注。它是用户记录，不是平台已验证回执。
- **版本（Revision）**：主稿或平台稿在本地留存的可恢复内容快照。
- **素材（Asset）**：由用户导入工作区并被稿件引用的本地文件。

### 7.2 平台稿状态

```text
未创建 → 草稿 → 待发布
              ├─ 用户已记录发布
              └─ 已归档
```

平台稿相对主稿还应显示：`与来源版本一致`、`可能已过期` 或 `来源未知`。这些是本地关系状态，不代表平台审核/发布状态。

### 7.3 文件与索引一致性

- Markdown 文件是正文唯一权威来源；SQLite 索引可从工作区文件重建。
- 数据库索引暂时不可用不能导致正文不可读或被自动重写。
- 文件写入采用安全保存策略；当磁盘写入失败时保留内存编辑内容并提示用户。
- Frontmatter 中 MVP 管理的字段范围必须明确；未知字段应原样保留，不得因编辑往返丢失用户自定义字段。

## 8. 主要业务流程

### 8.1 创建与编辑

1. 用户选择工作区并创建 Markdown 主稿。
2. 编辑器保存正文和用户支持的元数据，显示保存成功或失败。
3. 用户添加素材，插入相对路径引用并预览。
4. 用户可查看历史版本并非破坏性恢复。

### 8.2 生成平台稿

1. 用户选择主稿和目标平台（掘金、CSDN 或两者）。
2. 用户选择要发送给模型的内容，查看数据发送说明。
3. AI 生成一个或多个候选平台稿；应用展示原稿与候选内容。
4. 用户接受、编辑或放弃候选稿；接受后生成独立平台稿，不覆盖主稿和已有手工修改。
5. 主稿后续变更时，系统提示平台稿与其来源版本不同。

### 8.3 人工发布辅助

1. 用户选择平台稿并进入发布准备页。
2. 应用显示最终内容、平台格式提示、素材检查结果及规则局限。
3. 用户确认复制内容并打开对应平台页面，自行完成登录、粘贴和发布。
4. 返回 CreatorRelay 后，用户可选择记录外链和发布时间；未确认时保持未记录状态。

### 8.4 导入、外部修改与恢复

- 对重复文件名/路径冲突，展示差异并让用户选覆盖、另存或取消。
- 对应用外修改，检测并阻止自动覆盖；支持载入外部内容或另存副本。
- 恢复版本前展示版本时间和将被替换的当前内容；恢复结果作为新版本保留。
- 恢复备份前展示备份来源、工作区目标和潜在覆盖内容；取消不改变当前数据。

## 9. MVP 验收标准

### 9.1 功能验收

| ID | 验收条件 |
|---|---|
| MVP-01 | 在支持的 macOS、Windows 环境中安装并启动应用，可选择工作区并重启后重新打开同一工作区。 |
| MVP-02 | 创建、编辑并保存 Markdown 主稿；关闭并重启应用后正文与管理的元数据不丢失。 |
| MVP-03 | 导入包含相对路径图片引用的文章和素材后，预览可正确显示；重复导入不会静默覆盖。 |
| MVP-04 | 搜索可命中稿件标题、正文和标签；编辑外部文件后应用能够提示冲突并避免覆盖。 |
| MVP-05 | 从主稿分别创建掘金和 CSDN 平台稿；两者可独立编辑，任何一份编辑都不改变主稿或另一平台稿。 |
| MVP-06 | 更新主稿后，已有平台稿被标记为可能过期；重新生成时不会未经确认覆盖手工修改。 |
| MVP-07 | 可查看至少最近 30 个稿件版本并恢复任意留存版本；恢复前后版本均可访问。 |
| MVP-08 | 可创建手动备份并恢复到用户选定的位置；恢复冲突有预览和确认，取消操作不更改工作区。 |
| MVP-09 | AI 请求前显示发送范围并可取消；未选中的其他文档不随请求发送；密钥不会以明文写入工作区、SQLite 或应用日志。 |
| MVP-10 | AI 候选稿可被拒绝、复制、局部采纳或另存为平台稿；拒绝候选不改变原稿。 |
| MVP-11 | 发布准备页可预览、复制 Markdown 源文、导出平台稿文件并打开平台入口；列出本地图片素材供用户手动上传，应用不自动登录、上传媒体或发布。 |
| MVP-12 | 用户可以手动登记、修改和移除发布记录；没有用户输入时不伪造外部 URL 或发布成功状态。 |
| MVP-13 | 日志与错误提示不包含 API Key；AI/文件/备份失败时，已有内容不会静默丢失。 |
| MVP-14 | Markdown 文件损坏或 SQLite 索引丢失时，可报告问题；对可解析文件可重建索引，未能恢复的数据明确列出。 |

### 9.2 首发验证验收

- 完成 5 位目标用户的无指导任务测试，记录匿名化结果。
- 至少 4 位在 15 分钟内完成核心任务；若未达标，先修复关键流程可用性再扩大功能范围。
- 至少完成 macOS 与 Windows 各一次安装、重启、编辑、版本恢复和备份恢复测试。
- 对掘金/CSDN 的命名、格式提示及发布入口做人工核对，并在界面/文档注明核对日期；未核实的限制必须降级为提示。

## 10. 非功能需求

### 安全与隐私

- 只读写用户授权的 CreatorRelay 工作区和应用数据目录。
- AI 数据外发前由用户选择内容并知情；提供取消操作，默认不发送全工作区。
- API Key 使用操作系统凭据存储；禁止写入日志、Markdown、普通配置和 SQLite 明文。
- 任何打开外部网站、复制内容或恢复/删除操作均由用户主动触发。
- 错误、诊断和崩溃日志需避免记录文章正文及密钥；若需要诊断内容，须另行征得用户同意。

### 可靠性与数据安全

- 自动保存状态必须可观察；未落盘内容不能显示为保存成功。
- 文件写入采用原子替换或等效保护；异常时保留可恢复副本。
- 对索引和正文来源关系有明确说明，并提供索引重建能力。
- 版本和备份恢复须覆盖正文、Frontmatter、平台稿关联和素材引用；恢复后的路径引用应可验证。

### 可用性与维护

- 核心任务应可通过键盘和鼠标完成；破坏性操作在确认前提供清晰取消路径。
- 错误信息说明发生了什么、内容是否已保存、用户下一步可做什么。
- 数据格式需版本化；升级不能静默丢弃未知 Frontmatter 字段。

首版不设未经基准测试的性能数字。产品验证阶段记录启动、搜索、保存和预览的实际耗时，再决定是否形成正式性能预算。

## 11. 已确定与待验证决策

### 11.1 MVP 已定基线

- 首要用户为个人技术创作者，首要链路为本地 Markdown 多平台创作与人工分发。
- 首批目标平台为掘金、CSDN；产品支持范围不等于平台自动化许可或接口承诺。
- 自动发布、定时发布、账号会话托管、自动数据分析、MCP、第三方插件均不进入 MVP。
- 正文以 Markdown 文件为权威来源，SQLite 仅作可重建索引和结构化记录。
- 用户明确选择 AI 输入，结果经用户确认后才写回/另存。
- macOS、Windows 是 MVP 目标平台；Linux 暂缓。

### 11.2 开始实现前要验证的事实

1. **平台规则**：核对掘金、CSDN 当前 Markdown/图片/代码块等格式差异、发布入口和公开规则；留存验证日期与证据来源。
2. **人工发布体验**：确认“复制内容 + 打开平台 + 回来登记链接”在实际使用中足以减少重复劳动；不要用未经许可的页面自动化替代。
3. **桌面能力**：在 macOS、Windows 分别验证应用数据目录、系统凭据服务、打包及工作区权限。
4. **目标用户验证**：访谈/测试确认 Markdown 技术作者的工作流与 15 分钟任务是否具有代表性。

以上任何平台事实验证失败，都不自动扩大自动化范围；优先调整提示和人工流程。

## 12. 核心端到端试用任务

以一篇包含标题、代码块、至少一张本地图片的技术文章为任务材料，要求参与者：

1. 新建或导入主稿并完成一处编辑。
2. 为掘金、CSDN 各创建一份平台稿。
3. 至少编辑一份平台稿，并确认另一份没有被连带修改。
4. 检查预览和素材提示，进入人工发布准备页。
5. 复制内容并打开平台入口（测试环境可不实际提交公开内容）。
6. 返回并登记测试用发布链接或说明尚未发布。
7. 关闭并重新打开应用，查看内容和版本历史。

观察者不提供操作提示；遇到无法继续的情况，记录任务中断点，不代替用户完成。

## 13. 迭代顺序

1. **M0：可行性验证**——平台规则核对、OS 凭据/文件路径验证、目标用户任务验证。
2. **M1：本地内容基础**——工作区、Markdown 编辑/预览、搜索、素材、索引重建。
3. **M2：可恢复工作流**——自动保存状态、版本历史、手动备份/恢复、外部修改冲突处理。
4. **M3：双平台创作**——掘金/CSDN 平台稿、来源版本关系、差异提示和规则检查。
5. **M4：AI 与发布辅助**——BYOK、明确输入范围、候选稿采纳、复制/打开平台及手工发布记录。
6. **M5：首发验收**——macOS/Windows 打包回归、数据安全测试和 5 人可用性验证。

每阶段需有可演示产物及针对数据丢失、冲突、失败恢复的测试，不按模块数量判断完成度。

## 14. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 平台 Markdown 规则变化或存在差异 | 平台稿排版不符合预期 | 规则做成可更新的提示，显示验证日期；用户发布前预览；不承诺平台审核结果 |
| 用户把“发布记录”误认为平台回执 | 错误的内容状态 | 明确标注为用户手工记录；不自动声称已发布 |
| AI 改写导致原稿被覆盖 | 内容损失 | 候选稿与原稿隔离；应用前保存版本；每次写回须用户选择 |
| 外部编辑器和 CreatorRelay 并发修改 | 内容互相覆盖 | 冲突检测、明确选择、禁止静默覆盖 |
| 本地快照/备份占用空间或恢复不完整 | 数据不可用或磁盘压力 | 定义 30 版本保留、提示空间问题、恢复预览和跨平台恢复测试 |
| BYOK 被误解为本地 AI | 隐私争议 | 每次请求说明目标服务和发送内容，提供取消和最小化选择 |
| 系统凭据能力跨平台不一致 | 密钥落盘风险 | 按操作系统验证安全存储；不满足时禁用明文持久化方案 |
| 平台自动化期待过高 | 产品承诺失真 | 明确人工发布定位，不展示虚假的登录/发布能力 |

## 15. MVP 之后的候选方向

仅作为候选，需根据首发验证结果重新排序：

- 自动化发布或平台官方 API 接入（逐平台验证政策、接口和风险后单独立项）。
- 数据同步、运营 Dashboard 与 Analytics。
- 更多内容平台及其他内容形态。
- 连接外部 MCP Server 或提供受权限控制的 MCP 工具服务。
- 官方插件扩展，再评估第三方插件的签名、隔离和权限模型。
- 自动备份、加密异地备份与团队/云同步。
